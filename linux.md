2: mkdir = зробити директорію 
3: rm/rm-rf = видалити файл або директорію 
4: nano/vim = редактувати файл в терміналі 
5: touch = зробити файл 
6: chmod = змінати права

2: vim = треба привикнути/ефективніше 


## Як поглиблюватись? Навігація і робота з файлами 

1: find = шукає файли за назвою,типом,розміром,датою.Шукаю "наживо" тому повільніше,але точно 

2: locate = тоже шукає файли але по готовій базі,тому дуже швидко. Базу оновлюватись командою sudo updatedb

3: Three = показати структуру папок як дерево 

tree    вся структура 
tree -L 2    тільки 2 рівні вглиб 

для того шоб зрозуміти як влаштований проект якшо команди нема треба встановити sudo apt install tree


4: ln = створити посилання на файл 

ln -s /etc/nginx/sites-avaible/site /etc/nginx/sites-enabled/site

-s = створює символьне посилання аналог ярлика віндовс якшо видалити орігинал то посилання зламається 

без -s = створюється жорстке посилання ше одне імя для того самого incode файл живе поки існує хочаб 1 імя

для того шоб не копіювати файл в пару місць а посилатись на 1 класичний приклад = включення сайтів в nginx


stat = повна інформація про файл 

stat file.txt 

Показує розмір,права,номер incode,власника,кількість жорстких посиланнь і дати 

Для того шоб зясувати коли файл змінювали і хто власник 


file = визначити тип файлу 

file photo.jpg
photo.jpg: PNG image data 

Linux визначає тип за вмістом а не за розширенням 

Для того шоб поняти шо це за файл якшо розширення нема або воно бреше 


                 Потоки і перенаправлення 
                3 стандартні потоки 

в кожної програми є 3 канала:
    Потік                 Номер                        Шо це 
    stdin                   0   вхід,звідктипрограма бере данні 


     stdout                 1    простий вивід: результат роботи


     stderr                 2            вивід помилок 


Помилки йдуть окремим каналом шоб їх можна було відділити від результату 
                      

                      Перенаправление 

ls > files.txt                stdout в файл(Перезапускає файл)
ls >> files.txt               stdout в кінець файла (дописує)
ls /nope 2> errors.txt        тільки помилки (потік 2) в файл
command > all.log 2>&1        і вивід і помилки в 1 файл
command 2> /dev/null          викинути помилки ("чорна дира")

2>&1 = "потік 2 (помилки) відправ туда ж куда йде потік 1" Порядок важливий: перше >файл потім 2>&1
Для того шоб зберіграти логи скриптів приховувати непотрібні помилки 


Пайп | = передає вивід 1 команди на вхід іншої  так з малих команд збирається мощьний інструмент 

cat app.log | grep ERROR | wc =l  скільки рядків з ERROR в лозі 
ps aux | grep nginx          чи запущений nginx

Тому шо без пайпів неможна писати однорядники тобто вирішувати задачу одним рядком в терміналі 


               Змінні оточення 


це пара назва = значення яку система зберігає в памяті і передає всім програмам які запускаються 

env = показати всі змінні 
виводить список всіх змінних оточеня в вигляді назва = значення 

шукати конкетну:
env | grep HOME

тут вивід env передається через пайп grep який лишає тіки рядки з Home 

подивитись 1 змінну: 
echo $HOME
/home/marko77

$ перед назвою значить "підстав значення змінної" без знака команда просто надрукує слово Home 


Створення змінної:  проста  vs export

проста(локальна змінна):
NAME="Marko" іменно без пробілів між найм і лапками 
echo $NAME
змінну бачить тіки термінал програма і скрипт не бачать 


Export = змінна для всіх дочірніх програм 
export DB_PASSWORD="secret123"
тепер змінну бачать всі скрипти + програми які запущені з цього термінала 


Перевірка різниці: 
A="local"
export B="exported"
bash -c 'echo A=$A B=$B

bash -c = запускає новий баш він бачить тіки B бо її експортовано а А не існує 


Змінна тіки для 1 команди 
PORT=8080 node app.js 
змінна діє тільки для ціїє команди і більше ніде 


Видалити змінну 
unset   DB_PASSWORD
!всі змінні створені в терміналі через export зникають після закриття шоб вони були постійними їх треба записати в файл .bashrc


PATH: де система шукає програми 

PATH: список папок розділених ":"
echo $PATH 
Як це працює: 
коли пишеш git система по черзі переглядає папки через PATH і шукає файл git виконується перший знайдений 

Подивитись звідки саме запускається програма 
which git 

звідки береться: command not found: програма або не встановленна або лежить в папці якої нема в PATH саме так було з code в павершел вс код вже скачався але старий термінал ше не знав нової папки в PATH

Додати папку в PATH:
export PATH=$PATH:/opt/mytool/bin
$PATH підставляє старий список 
:/opt/mytool/bin дописує в кінець нову папку 

!ніколи не пиши export PATH=/opt/mytool/bin без $PATH:
так ти затреш весь список і перестануть працювати навіть cd і ls


Файли автозапуску: .bashrc, .bash_profile, .profile 
це файли в домашній папці (~) які bash робить автоматично все шо в них записано (export,аліаси) діє в кожному новому сенсі 
вони приховані і починаютсья з крапки тому шоб їх побачити 
ls -a ~
-a показує всі файли разом з прихованими 

login shell = коли входиш в систему (ввів логін пароль або через SSH)
інтерактивний shell = коли відкриваєш ше 1 термінал будучи в системі 

на практиці (Ubuntu) всьо своє пишуть в .bashrc бо в profile вже стоїть код який сам підключає .bashrc при вході тож настройки діють в 2 випадках 


Приклад: зробити змінну і аліас постійними
echo 'export EDITOR=nano' >> ~/.bashrc
echo 'alias ll="ls -la"' >> ~/.bashrc 

>> = дописує рядок в кінець файла Не плутай з >, бо > перезапише весь .bashrc!
alias створює команду: тепер ll = ls -la

застосувати змінні без запуску терінала 
source ~/.bashrc
source = виконує файл в поточному терміналі без нього змінні будуть працювати тіки в змінному вікні 


Основне:
env                          # усі змінні
echo $HOME                   # значення змінної
NAME="x"                     # локальна змінна
export NAME="x"              # змінна для дочірніх програм
unset NAME                   # видалити
which git                    # де лежить програма
export PATH=$PATH:/my/dir    # додати папку в PATH
echo 'export X=1' >> ~/.bashrc   # зробити постійною
source ~/.bashrc             # застосувати зміни
